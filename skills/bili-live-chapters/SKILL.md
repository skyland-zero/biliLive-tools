# 直播录像 → B站章节 + 置顶评论时间轴

把一段没有字幕的直播录像，整理成两段**能直接粘进 B站投稿页和评论框**的文本。
先读 `references/bilibili-rules.md`（B站硬规则 + 实测数据），再按下面流程做。

## 交付物

### 依赖与环境

| 东西 | 说明 |
| --- | --- |
| 必需 | `ffmpeg` / `ffprobe`、`python3`、`numpy` |
| 语音转写 | `sherpa-onnx` + SenseVoice-Small(int8) + silero-vad（纯 CPU，不用 torch） |
| 音乐识别 | `shazamio`（Shazam 全片扫描） |
| 图像/抽帧 | 可选，只有封面类脚本才需要 `opencv-python`、`Pillow` |
| 环境变量 | `BILI_ASR_HOME`（venv/模型/输出的落地目录，默认 `D:\asr`）、`ASR_MODEL_DIR`（模型目录，默认 `$BILI_ASR_HOME/models`） |

装在空间充足的盘上。Windows 上装到 C 盘很容易把系统盘撑满（本项目开发机就是把 venv 和模型放 D 盘）。

### 写哪里、叫什么名

写到**视频所在目录**（和素材放一起，用户好找），文件名**照搬视频文件名**（去掉 `.mp4`）+ 后缀，
多场直播共存时才能一一对应：

| 文件 | 用途 |
| --- | --- |
| `<视频文件名>.txt` | 合订版：标题 / 简介 / 章节 / 时间轴 |
| `<视频文件名>-章节.txt` | 只有章节行（≤10 行），粘到投稿页「分段章节」 |
| `<视频文件名>-置顶评论.txt` | 粘成置顶评论（**≤900 字，含第一行标题**） |

例如视频 `2026-10-14 00-07-29-912 我来啦-合并-弹幕版.mp4` →
`2026-10-14 00-07-29-912 我来啦-合并-弹幕版-章节.txt`。**不要**用 `20261014.txt` 这种日期简写。

中间产物（弹幕 dump、特征数组、联系人图）放一个缓存目录，别丢到用户素材目录里，例如
`<项目>/.pi/tmp/ch<MMDD>/`。

## 投稿标题（交付后的下一步）

**标题规范不放进本 skill**，单独维护一份（比如素材目录里的 `B站投稿标题规范.md`；本 skill 只管章节/时间轴/简介）。别拄两份进不同地方，必分叉。

需要给标题候选时：

```bash
python scripts/title_materials.py "<视频文件>" --analysis "<视频名>-分析" \
    --chapters "<视频名>-章节.txt" --pinned "<视频名>-置顶评论.txt" \
    --out "<视频名>-分析/04-标题素材.txt"
```

它会把“开播时间 → 建议的 `MM.DD午/晚` 标注”、钩子候选（带字数，≤9 字的标“可直接用”）、
本场歌单、环节名、固定标签一次抽好；拿这份素材 # 再读那份规范里的模板写标题。

规范里两条跨主播通用的硬规则（没读规范时也要遵守）：

1. **名字必须在标题里**（发布方不是主播本人，作者栏给不了这个信息）；
2. **钩子压在前 20 字内**——`{钩子}{【主播 公会】}{MM.DD}{午/晚} 录播`，钩子 ≤9 字。

注意：规范第八节那份“素材库歌单”是旧的（实测缺 20+ 首、还有一首没唱过的），
**歌单一律以每场的 `01-歌曲清单.txt` 为准**。

## 先走这条：语音转写 + 音乐识别（ASR 为主、弹幕为辅）

2026-10 之后的做法：**先转写语音、再识别音乐**，最后拿弹幕补味道。只看弹幕会写错——弹幕里的歌名
往往只是“点歌请求”，不代表真的唱了（实测：10-14 那场弹幕说“一点点心动”，音频里根本没出现，
真正唱的是《一场游戏一场梦》）。

环境放在 `BILI_ASR_HOME`（默认 `D:\asr`）下：venv `$BILI_ASR_HOME/venv`、模型 `$BILI_ASR_HOME/models`、
日志/输出 `$BILI_ASR_HOME/logs`、`$BILI_ASR_HOME/out`。

```bash
# 0) 一次性：建 venv + 装包（用 uv；不要装 torch —— SenseVoice 走 onnxruntime 就够）
export BILI_ASR_HOME=${BILI_ASR_HOME:-D:/asr}
uv venv "$BILI_ASR_HOME/venv" --python 3.12
uv pip install --python "$BILI_ASR_HOME/venv/Scripts/python.exe" shazamio sherpa-onnx soundfile
# 模型三件套：model.int8.onnx(228MB) + tokens.txt + silero_vad.onnx
#   从 HuggingFace csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17 拉
#   （GitHub release 的大 tarball 容易断流损坏，别用它）

# 1) 语音转写（~15x 实时：2h16m 约 9 分钟、4h48m 约 20 分钟）
"$BILI_ASR_HOME/venv/Scripts/python.exe" scripts/asr_transcribe.py "<视频>" --outdir $BILI_ASR_HOME/out/xx --mode window --window 20

# 2) 音乐扫描（每 30s 取 12s 送 Shazam）
#    命中率参考：室内/唱歌多的场 ~70%，户外散步场 ~35%
"$BILI_ASR_HOME/venv/Scripts/python.exe" scripts/shazam_scan.py "<视频>" --out $BILI_ASR_HOME/logs/scan_xx.jsonl --step 30

# 3) 内容摘要（滤掉“谢谢XX哥的虎粮”这类噪音，按分钟聚合，♩ 标歌名）
"$BILI_ASR_HOME/venv/Scripts/python.exe" scripts/asr_digest.py --asr $BILI_ASR_HOME/out/xx --songs $BILI_ASR_HOME/logs/scan_xx.jsonl --out $BILI_ASR_HOME/out/xx/digest.txt

# 4) 落成文档（存视频同目录 <视频名>-分析/：分析报告 / 歌曲清单 / 内容摘要 / 语音转写 / 原始数据）
"$BILI_ASR_HOME/venv/Scripts/python.exe" scripts/build_analysis_docs.py --video "<视频>" --asr-dir $BILI_ASR_HOME/out/xx \
    --scan $BILI_ASR_HOME/logs/scan_xx.jsonl --outdir "<视频目录>/<视频名>-分析" --notes notes.txt [--title-map titles.json]
```

拿到 `digest.txt`（每小时几十行，带 ♩ 歌名）后怎么写章节：

- **边界卡在“环节变化”或“歌曲开始”上**（有歌就卡在歌的起点，观众好空降）；
- 标题内容用 ASR 原话（如 `连麦PK｜对面拿豆汁整活`），歌名用 Shazam 结果；
- **弹幕只用来补味道**（梗名、网络用语）；观众点歌不能当作“她唱了”；
- 歌单也是交付物的一部分（`01-歌曲清单.txt`），观众爱看。

### ASR 已知坑

- **人名/梗名必错**：实测观众昵称“某布哥”会被转写成“手叔波哥”、“豆汁”会写成“斗汁”，
  写文案时不要照抄 ASR 的人名/梗名——先用弹幕核对再落字。
- 唱歌段 ASR 会乱码（日语/韩语段尤甚），正常：**歌名一律以 Shazam 为准**。
- 礼物致谢占直播一大半句子（“谢谢XX哥的情书/留声机/魔法书/虎粮”），摘要脚本会滤掉，**交付文案也不写这些**。
- 别用 VAD 模式转长视频：连续说话会被并成几分钟一块，SenseVoice 超 30 秒明显退化；用 `--mode window --window 20`。
- 两边不一致时以 ASR 为准（她说的话 > 观众刷的弹幕）。

## 流程

### 0. 先确认三件事

1. **哪条视频**：优先用 `*-合并-弹幕版.mp4`（时间轴与 `-合并.xml` 对齐）。**不要**用原始分段
   `.ts`，否则时间戳全错。
2. **弹幕 XML**：优先 `*-合并.xml`；没有就用同名 `.xml`。完全没有弹幕时跳过第 2/4 步，
   只靠音频 + 画面，标题要写得更保守（话题级，别断言歌名）。
3. **时长与结构**：`ffprobe -v error -show_entries format=duration -of default=nw=1 <video>`
   拿到总秒数；一次性算好 `hh:mm:ss` 精度。

一条录播通常由多段 `.ts` 合并而成（文件名的标题会变，例如「我来啦」→「不挖土豆来做饭啦」），
合并后时间轴是连续的，**不用**按段切章节。

### 1. 弹幕 dump

```bash
python <skill>/scripts/dump_danmaku.py "<合并.xml>" "<cache>/danmaku.txt"
```

得到 `[MMM:SS.d] 用户: 内容`。顺手看每 5 分钟刷屏统计（决定哪些点是🔥高能）。

### 2. 音频分析（找"安静/忙碌/唱歌"段）

```bash
python <skill>/scripts/audio_feat.py "<video>" "<cache>/feat.npy"    # 2h 片子约 2-3 分钟
python <skill>/scripts/audio_report.py "<cache>/feat.npy"            # 每分钟 dB/频谱 + 30s 强度图
```

用途：`quiet%` 高的分钟＝在忙别的（做饭/洗碗/打游戏低头操作）；dB 掉到 -45 以下＝长时间没说话；
谱质心高的段可能有唱歌/伴奏（无伴奏清唱只能靠弹幕佐证）。

### 3. 弹幕统计（找话题转折 + 名场面）

```bash
python <skill>/scripts/danmaku_moments.py "<cache>/danmaku.txt"
```

输出：每分钟条数、复读刷屏（同一句 ≥3 次）、关键词簇、最大空档。复读刷屏是**最可靠的名场面信号**：

| 弹幕信号 | 含义 |
| --- | --- |
| `发了` / `出盾` 密集 | 抽奖出货名场面 |
| `[大哭]` / 😭 刷屏 | 走心/唱歌环节（标题写“走心环节”，**别**照抄成“弹幕大哭刷屏”） |
| `💃` 刷屏 | 唱跳/魔性片段（标题写“唱跳环节”） |
| `对面` / `上豆汁` / 双人画面 | 连麦 PK（左自己右对面，切割成两半的画面） |
| 手机屏幕怼镜头 + 棋盘 | 小游戏环节（五子棋/象棋），常伴随打赌金额 |
| `好听` `[送花]` `[心动]` | 点歌/清唱 |
| `886` `晚安` `下播` + 最后 1-2 分钟 | 下播（收尾章节写到主播的收尾环节就行） |

### 4. 视觉抽样（确认场景，别猜）

```bash
python <skill>/scripts/contact_sheet.py "<video>" "0,120,240,...,1320" "<cache>/A.jpg" --cols 4
```

每 2 分钟一帧拼成图，然后用 `read` 工具**看图**（这是必要步骤，别跳过）：

- 场景切换（厨房 → 客厅 → 沙发 → 手机屏幕）＝章节边界
- 单人 vs 双人分屏＝PK/连麦的起止
- 主播离场（只剩空景）＝主播离开时段
- 结尾是否有挥手/黑屏

### 5. 边界钉死

对每个候选边界（PK 起止、场景切换、游戏起止），用 15-30s 步长再抽一次确认到 ±15s。
抽帧脚本每次只调 ffmpeg seek 一帧，几十帧很快。

### 6. 归类成章节

**先按规则限制裁到 ≤10 章**（B站硬限制，见 references），再做长期覆盖：

1. 按"话题/场景/玩法"聚类，合并相邻小话题
2. 每章时间点对齐到画面或弹幕的实际起点（±15s 都行，别卡在句子中间）
3. 标的优先级：PK/连麦 → 唱歌点名场面 → 小游戏 → 抽奖福利 → 普通唠嗑
4. 平均一章 10-15 分钟；2h 片子给 8-10 章最舒服
5. 标题 ≤16 字、不要 emoji；**默认平实**（信息第一），梗要带一句解释，别只丢梗名

### 7. 写文件 + 自检

写完后两个校验器都要跑：

```bash
python <skill>/scripts/check_chapters.py "<章节.txt>" --duration <视频总秒数>
python <skill>/scripts/check_pinned.py   "<置顶评论.txt>" --duration <视频总秒数>
```

`check_pinned.py` 会抓出“格式不对 / 时间点超出片长 / 时间没递增 / 注释体残留 / 超 900 字”
——**视频 ≥1 小时时，置顶评论的时间戳同样必须是 `hh:mm:ss`**，写成 `01:37` 会被 B 站
当成 1 分 37 秒，点下去直接跳错位置。

- [ ] 第一章 `00:00:00`（或 `00:00`）
- [ ] 章节数 2-10
- [ ] 相邻间隔 ≥5s，时间戳严格递增，最后一章不超总时长
- [ ] 每个标题 ≤16 个汉字、无 emoji
- [ ] 视频 ≥1 小时用 `hh:mm:ss`，<1 小时用 `mm:ss`
- [ ] 置顶评论 **≤900 字、含第一行标题**（实测 838/843 能发、974 被拒；**校验器数的是整份文本**）
- [ ] 置顶评论的时间戳格式与章节一致，长视频的 ≥1h 条目写 `1:43:16` 而不是 `103:16`
- [ ] **不要加页脚**：时间轴到最后一个条目就结束，**别**写“素材是…时间”“最想看哪段？评论区点名”
      这类收尾语（用户明确不要）

### 8. 交付

在聊天里**直接贴出章节文本**（用户要复制），再说一句文件路径、以及置顶评论有多少字。
不要只丢文件路径就结束。

## 关键经验

- **分清同住室友和连麦对象**：一起住的室友**在镜头里**（试吃、同框、一起出门），不会“视频连线”；
  连麦/视频对面是另一位主播（有自己的粉丝牌、独立直播间）。写错方向会被当场抓出来。
- **歌名按社区/主播的叫法写，不要照搬音乐库标题**：实测看得最多的一首下播曲，音乐库里叫《不灵不灵》
  （hook 是 "Bling bling"），但直播间和弹幕里从主播到观众一律写同音的另一个写法（实测弹幕 6:0）。
  库里标题只是用来定位歌曲的，交付文案要用观众认识的写法；拿不准就看弹幕怎么写。
- **不写“注释体”**：不要出现 `《歌名》=主播的黑话叫法`、`(1:54 弹幕点的歌)`、`A vs B 之争`、
  `学歌法:慢速→中速→快速` 这类等于号 / 箭头 / 括号备注——那是写给自己看的，观众看了莫名其妙。
  直接写内容：`下播曲《歌名》`、`《歌名》`、`A 还是 B 好吃`。
  括号只留给必要信息（如 `《歌名》(某某翻唱版)` 标明版本）。
- **弹幕少的场次**（2 小时只有几百条）很常见：不要因为弹幕稀就编内容；标题写话题级
  （"边走边聊｜..."），把细节交给置顶评论时间轴。
- **抽帧标签别用冒号**：ffmpeg `drawtext` 的 `text='1:13:00'` 会被当成参数分隔符，标签会渲染错。
  用 `73m00` 这种写法（脚本里已经这么处理）。
- **清唱很难自动识别**：本项目 `biliLive-tools` 的「章节生成」用四路信号（音频特征 + ASR music 分数 +
  弹幕关键词 + 模型复核）才敢下结论；手写时只在弹幕明确刷 `好听/送花/大哭` 时才写"唱歌"。
- **别把弹幕玩梗照抄进标题**：收尾时观众常刷日语谐音的骂人词（笨蛋之类的音译），这类词不要进章节标题和时间轴，走到主播的收尾歌/告别语为止就行。
- **不写金额/赌注，也不写抽奖礼物类条目**：五子棋、连麦这类玩法里常拿钱打赌（“赢一把50块”“-50”），
  标题和时间轴都换成中性描述（`五子棋擂台赛｜和观众对局`、`五子棋分出胜负`）；**抽奖、出货、
  贵族续费、礼物榜**这类条目（“抽奖连爆”“小字本出货”“唠唠哥续费公爵”）**章节标题和时间轴都不要写**，
  牵扯花钱的话题（机票、送礼）也一样换成“行程/团播”这种说法。
- **不写私人寒暄/致谢**：`晚安某某哥`、`感谢榜一哥`、`互道晚安`、单独一条观众口头禅 这类对某个人的
  问候、致谢、单条口头禅都不要进时间轴——那是观众之间的寒暄，对看回放的人没有信息量。
- **时间轴条目写内容，不写弹幕行为**：每条应该是“这一段是什么”（歌名、环节、玩法、梗名），
  例如 `2:13:14 XX下播曲(下播曲)`。**不要**写“弹幕刷屏/齐刷/弹幕集体/大合唱”这类描述——
  弹幕刷得凶只说明观众在发，推不出“一起唱了”，而且这种写法对观众也没信息量。
  （需要保留“这是个高能点”时，用行首的 🔥 就够了）。
- **梗要带解释，别只丢梗名**：标题得让没看过直播的人也看懂。反例 `连麦PK｜豆汁来啦`
  （外部观众不知道“豆汁”发生了什么）；正例 `连麦PK｜对面拿豆汁整活`。
- **默认写平实版，别自作主张卖萌**：语气词版（“开播啦”“来啦”“开战”）用户看过之后放弃了，
  除非用户明确说“可爱一点”“俏皮一点”，否则按平实写；两种版本可以各存一份供选。
- **旧场次的成品要返工一遍**：以前做的 txt 常超出 10 章、带页脚、或写作风格已过时（“刷屏”“赢一把50块”）。
  改名归档时顺手跑一遍 `check_chapters.py` 并对照本 skill 的标题写法，别直接沿用到新视频上。
- **别用 `-ss` 精确到关键帧**：抽帧用 `-ss <秒> -i` 即可，误差 <1s，不影响章节。
- 如果**本机装了 biliLive-tools 且「设置 - AI配置」配好了 ASR/LLM**，优先用软件里的
  「工具 - 章节生成」（它是本项目自带实现，输出格式与本 skill 一致）；本 skill 用于没有 AI
  配置、或需要人工校对每个边界、或软件结果明显不对时。

## 脚本

| 脚本 | 作用 |
| --- | --- |
| `scripts/asr_transcribe.py <视频> --outdir <目录>` | SenseVoice+silero VAD 转写（默认 20s 固定窗口，~15x 实时） |

| `scripts/title_materials.py <视频> --analysis <目录> ...` | 抽投稿标题素材（场次标注/钩子候选/歌单/环节名/标签） |
