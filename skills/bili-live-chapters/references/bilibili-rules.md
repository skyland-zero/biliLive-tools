# B站章节 / 时间轴 规则（含实测依据）

## 一、分段章节（改进度条的那个）

来源：B站帮助《分段章节使用指南》（被多处转载的原文）＋本地实测。

| 项目 | 要求 |
| --- | --- |
| 稿件状态 | 所有人可见；**时长 > 5 分钟**；非互动视频 |
| 首章 | 起始时间固定 `00:00`，且该段时长 ≥1 秒 |
| 其余章节 | 每段时长 ≥5 秒（相邻时间戳间隔 ≥5s） |
| **章节数量** | **最少 2 个，最多 10 个**（含首章） |
| 章节标题 | 少于 16 个汉字 / 32 个英文字母（按"≤16 字"控制最稳） |
| 时间格式 | `MM:SS` 或 `HH:MM:SS`；**视频 ≥1 小时用 `hh:mm:ss`** |
| 章节范围 | 覆盖整片：第一章 00:00 到最后一章接片尾 |

### 两条配置路径（都能用）

1. **文本粘贴框**：投稿页/稿件管理 →「分段章节」，框内直接粘多行文本，一行一章：
   ```
   00:00 开场
   00:30 Bilibili名字的由来
   01:24 Bilibili有几个名字
   ```
2. **切割章节 UI**：稿件管理 →「个性化配置」→ 分段章节 → `切割章节`（N-1 次）→ 逐项填
   `起始时间` + `标题`；APP 端：稿件管理 → 更多 →「视频章节」→ `+ 添加章节`。

### 标题注意事项

- 中文标点可用：实测线上章节标题里出现过 `+` `&` `？` `《》` `（）` `，` `·`
- **emoji 不要放**：线上章节标题没见过带 emoji 的，而置顶评论里可以随便用
- 不要以序号/标点结尾（`1. xxx`、`xxx。`），粘贴框和 LLM 输出都容易带脏字符

### 标题写法（都是从实际返工里总结的）

- **≤16 字**，不要 emoji（线上没见到带 emoji 的章节标题）
- **让没看过直播的人看懂**：梗要带解释，`对面拿豆汁整活` ✅、`豆汁来啦` ❌
- **不写弹幕行为**：`弹幕刷屏/齐刷/弹幕集体/大合唱` 都不写；需要标高能就在行首放 🔥
- **不写金额和赌注**：`赢一把50块` → `和观众对局`，`赌注50块` → `分出胜负`
- **默认平实**，除非用户要求“可爱一点”；俏皮语气词版会被打回
- 中文标点可以用（实测线上标题里出现过 `+` `&` `？` `《》` `（）` `，` `·`）
- 不要以序号/标点结尾（`1. xxx`、`xxx。`）

## 二、置顶评论时间轴

- 置顶评论实测上限 **≈900 字**（含第一行 `📌 …` 标题）：838/843 字能发出去，974 字被 B站 拒；
  所以交付目标 **≤860 字**，并且**数的是整份文本**（校验器早期只数正文，导致 974 报了通过）
- 根评论里的 `MM:SS` / `HH:MM:SS` 会变成可点击跳转
- **视频 ≥1 小时时，时间轴必须写 `hh:mm:ss`（硬规则，不是建议）**：写 `01:37` 会被当成 1 分 37 秒，
  点下去直接跳错位置——`00:46` 更是会跳成 46 秒。本项目自己也是这么实现的：
  `packages/shared/src/chapter/timeline.ts` 的 `formatTime(seconds, withHours)` / `renderTimelineText()`
  （`withHours = duration >= 3600`），章节与时间轴共用同一套格式化，所以两边格式必须一致。
  短于 1 小时的视频才用 `mm:ss`（本 skill 里本章节用 `00:00:00` 是刻意的 - 章节时间戳位宽一致更好看）。
- 交付前跑 `scripts/check_pinned.py <置顶评论.txt> --duration <秒>`：它会抓格式不对 / 递增错误 /
  超出片长 / 超 900 字 / 注释体残留。
- 时间轴是"置顶评论"，**不会**给进度条加章节；两者互不影响，可以都发

## 三、常见误解

- `简介里写时间戳` ≠ 章节。简介/评论的时间戳只是跳转链接，进度条分段必须在上面那两条路径里配置。
- `高能看点` ≠ 分段章节。高能看点是在进度条上打点标热点（数量限制更宽松，实测见过 12 个点）；
  分段章节是把视频切成连续段落（上限 10）。两者可以同时开。
- 章节不是"越多越好"：10 章上限下，2 小时片子给 8-10 章最舒服。

## 四、实测依据（可复验）

```bash
python <skill>/scripts/probe_bili_limits.py            # 默认扫 ~1000 个长视频
```

原理：`api.bilibili.com/x/player/v2?aid=&cid=` 返回 `view_points`：

- `type=2` 且 `from < to`、覆盖 `[0, duration]` → **分段章节**
- `type=1` 且 `from == to` → 看点类标记（另一个功能）

2026-10 实测结果（扫 1500+ 个 >20 分钟的视频）：`type=2` 的分段章节**最多只出现 10 个**，
345 分钟的录播、156 分钟的演唱会都正好卡在 10；`type=1` 的看点最高见过 12 个。
这与帮助文档"最少2个，最多10个"一致。

## 五、参考实现（同一个仓库）

`biliLive-tools` 自带「工具 - 章节生成」（`packages/shared/src/chapter/`）：

- `renderChapterText()`：时长 ≥1h 输出 `hh:mm:ss`，一行一章 `时间 标题`
- 默认「章节数量上限 / 最小间隔 / 标题字数上限」= **20 / 60 秒 / 16 字**
  （20 是软件侧默认值，B站真实上限是 10，按 10 写安全）
- `renderTimelineText()`：置顶评论时间轴，默认 60 条 / 900 字
